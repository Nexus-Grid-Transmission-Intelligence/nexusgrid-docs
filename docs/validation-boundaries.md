# Validation Boundaries

This document defines the boundaries of the current Nexus Grid public demonstration environment and messaging.

## Demonstration Environment Limitations

The public demonstration environment is intended to communicate coordination concepts. It is not presented as a production grid operations system.

It can be used to discuss:

- Modeled restoration sequencing.
- Dependency-aware propagation behavior.
- Replay visibility.
- Plateau detection.
- Coordination boundaries.
- Structured trace generation.

It should not be used as evidence of:

- Live utility deployment.
- Field-validated operational performance.
- Outage reduction.
- ROI improvement.
- Predictive accuracy.
- Automated operational control.

## Non-Production Status

Public Nexus Grid materials should be understood as demonstration and modeling materials unless a separate validated deployment context is explicitly documented.

The current public site does not claim:

- Production deployment.
- Utility adoption.
- Live integration with operational systems.
- Certified reliability impact.
- Replacement of operator review.

## Assumptions

Demonstrations may assume:

- A modeled topology.
- Represented dependencies.
- Defined recovery steps.
- Modeled constraints.
- Runtime trace generation.

Those assumptions are useful for communication and review, but they do not automatically represent a specific utility system.

## Model Boundaries

The model boundary is focused on coordination behavior, not complete grid simulation.

The current public description does not claim to include:

- Full AC power-flow simulation.
- Protection relay behavior.
- EMS or SCADA production integration.
- Crew dispatch optimization.
- Market operations.
- Asset failure prediction.
- Weather prediction.
- Autonomous grid control.

## Appropriate Interpretation

Nexus Grid demonstrations are best interpreted as structured ways to inspect and discuss modeled restoration behavior.

They can help reviewers ask better questions:

- Why did the modeled sequence slow?
- Which dependencies shaped the path?
- Where did propagation remain local?
- What trace evidence supports the replay?
- Which coordination boundary deserves more attention?

They do not prove that a real-world operational outcome will occur without deployment-specific validation.
